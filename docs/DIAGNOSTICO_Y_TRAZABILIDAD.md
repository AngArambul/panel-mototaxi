# Diagnóstico y trazabilidad de Mototaxi

Revisión de `panel-mototaxi` para la entrega local `entrega-2026-11-23`. Los identificadores A1, A2 y A3 corresponden a las tres actividades descritas en la consigna entregada. Los requisitos específicos del docente más allá del texto pegado quedan por confrontar con su rúbrica y su índice completo.

## Diagnóstico de partida

El proyecto existente usa Laravel 12.72.0, PHP CLI 8.2.12, Composer 2.10.3, Breeze 2.4.2, Sanctum 4.4.0 y PHPUnit 11.5.57. Vite 7.3.8, Tailwind 3.4.19, Alpine 3.17.5 y Axios ya estaban declarados. El entorno también usa Node 26.13.0 y npm 11.20.0. PHP tiene `pdo_pgsql` y `pdo_sqlite`. La instalación local usa PostgreSQL 18.6, consultado en modo lectura. Las pruebas usan SQLite en memoria. Se preservan tanto PostgreSQL como el archivo SQLite preexistente. La demostración utiliza una base nueva separada.

Ya existían autenticación Breeze, perfil, un panel de despacho y una API con Sanctum y un puente de webhook. La web registraba el rol `PASAJERO`. Faltaban comprobación de cuenta activa y pantallas de administración. La autorización de despacho ya requería una cuenta de propietario Node. El panel conserva ese comportamiento. Las rutas de despacho estaban sin nombre y los formularios dependían de peticiones JavaScript. La lógica del puente HTTP vivía en los controladores. El README aún describía el esqueleto del framework.

El servicio Node es la fuente de unidades, viajes, GPS y mensajes. El panel consulta esos registros mediante la cuenta de propietario del servicio. Las tablas Laravel administran identidades web. El webhook de Laravel reenvía las solicitudes al receptor de Node. La versión archivada hacía respuestas automáticas en PHP. Consulte el código archivado y el informe de auditoría conservado junto al proyecto Android para reconstruir esa transición.

La línea base ejecutó 31 pruebas y 78 aserciones con SQLite en memoria. La entrega ejecutó 43 pruebas y 201 aserciones. Los resultados están en [PHPUnit](evidencias/phpunit.txt). El respaldo previo incluye copia SQLite validada con `quick_check = ok` y volcado PostgreSQL de 32 953 bytes con catálogo legible mediante `pg_restore --list`. El listado del volcado comprueba que se puede inspeccionar. Una restauración en una base aparte sigue siendo una comprobación distinta. Se aplicó en PostgreSQL la migración aditiva para `auth_version` después del respaldo y se comprobaron los mismos conteos de cuentas y roles antes y después.

La revisión inicial de Git devolvió «not a git repository». Se creó un repositorio local `main` y se registró el punto de partida en `3bcabf0`. El archivo `.env` está excluido. Se desconoce si alguna copia anterior publicó credenciales. No se indicó un remoto.

Prioridad inicial: proteger acceso de usuarios deshabilitados y operaciones sobre cuentas, mantener aislados los permisos de las dos aplicaciones, verificar la persistencia y conservar las rutas compatibles. Después, registrar pruebas, evidencia de interfaz y los pasos de entrega.
